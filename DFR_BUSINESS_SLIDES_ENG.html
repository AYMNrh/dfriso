04 · Direct answers

The three recurring questions — settled

Q1

"Did we lose information?"No

No, nothing is lost. All 54,855 occurrences have a documented decision (100% coverage). The 14,513 exclusions are 100% justified with a loss assessment: 11,803 XML wrappers (children handled individually), 1,631 contact details, 460 card details, 352 signature/technical details and 267 other scope exclusions. The 2,710 non-wrapper exclusions are proposed decisions for expert review; raw-source traceability uses raw_message_reference. No field disappears: you can always trace back to the source message.
Q2

"Can we trace the transformations?"Yes

Yes, 100%. 38,912 mappings link every source field to its table.column target, both ways. One mapping CSV per version + a consolidated matrix. Every non-derived final field has verified lineage: 0 orphans. In audit, "where does this column come from" is an exact XML path, not an opinion.
Q3

"Why so many tables?"0:n accepted

ISO 20022 is repetitive with an unknown "n": 0, 1 or n intermediaries, charges, remittances, status events. Before: one table with glued lists (ARRAY<STRUCT>) — each list is a table in disguise. Now: 14 tables, each repeated list becomes a real table joined by payment_id. One table = one grain.
